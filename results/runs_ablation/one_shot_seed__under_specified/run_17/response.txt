Creating a CI/CD pipeline for a fraud detection model involves three key components: the Python pipeline module, the pytest test file, and the GitHub Actions workflow. Below, I'll provide a detailed example of each component. 

### Python Pipeline Module

Let's assume that your fraud detection model is a simple logistic regression for illustration purposes. The module will cover data loading, preprocessing, model training, and evaluation.

```python
# fraud_detection_pipeline.py

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score
import joblib

# Set random seed for reproducibility
RANDOM_SEED = 42
np.random.seed(RANDOM_SEED)

def load_data():
    # For this example, we'll create synthetic data
    np.random.seed(RANDOM_SEED)
    data_size = 1000
    X = np.random.rand(data_size, 10)
    y = np.random.randint(0, 2, data_size)
    return X, y

def preprocess_data(X, y):
    X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=RANDOM_SEED)
    return X_train, X_test, y_train, y_test

def train_model(X_train, y_train):
    model = LogisticRegression(random_state=RANDOM_SEED)
    model.fit(X_train, y_train)
    return model

def evaluate_model(model, X_test, y_test):
    y_pred = model.predict(X_test)
    accuracy = accuracy_score(y_test, y_pred)
    return accuracy

def save_model(model, file_path='fraud_detection_model.pkl'):
    joblib.dump(model, file_path)

def main():
    X, y = load_data()
    X_train, X_test, y_train, y_test = preprocess_data(X, y)
    model = train_model(X_train, y_train)
    accuracy = evaluate_model(model, X_test, y_test)
    print(f"Model accuracy: {accuracy}")
    save_model(model)

if __name__ == "__main__":
    main()
```

### Pytest Test File

Now, let's create a pytest test file to ensure each function in the pipeline works as expected.

```python
# test_fraud_detection_pipeline.py

import pytest
from fraud_detection_pipeline import load_data, preprocess_data, train_model, evaluate_model
import numpy as np

# Set random seed for reproducibility in tests
RANDOM_SEED = 42
np.random.seed(RANDOM_SEED)

def test_load_data():
    X, y = load_data()
    assert X.shape == (1000, 10)
    assert y.shape == (1000,)
    assert set(y) == {0, 1}

def test_preprocess_data():
    X, y = load_data()
    X_train, X_test, y_train, y_test = preprocess_data(X, y)
    assert X_train.shape[0] == 800
    assert X_test.shape[0] == 200
    assert y_train.shape[0] == 800
    assert y_test.shape[0] == 200

def test_train_model():
    X, y = load_data()
    X_train, _, y_train, _ = preprocess_data(X, y)
    model = train_model(X_train, y_train)
    assert model is not None

def test_evaluate_model():
    X, y = load_data()
    X_train, X_test, y_train, y_test = preprocess_data(X, y)
    model = train_model(X_train, y_train)
    accuracy = evaluate_model(model, X_test, y_test)
    assert 0 <= accuracy <= 1

```

### GitHub Actions Workflow

Finally, here's a GitHub Actions workflow to automate the running of tests whenever you push to the repository.

```yaml
# .github/workflows/ci.yml

name: CI

on:
  push:
    branches:
      - main
  pull_request:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout repository
      uses: actions/checkout@v2

    - name: Set up Python
      uses: actions/setup-python@v2
      with:
        python-version: '3.8'

    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install numpy pandas scikit-learn joblib pytest

    - name: Run tests
      run: |
        pytest
```

This setup creates a CI/CD pipeline that includes a Python module for your fraud detection model, a test suite to validate it, and a GitHub Actions workflow to ensure everything runs smoothly when changes are made. The use of random seeds ensures that every run is reproducible, whether it's a training or testing phase. Adjust the pipeline and tests as needed to fit your actual data and model complexity.
